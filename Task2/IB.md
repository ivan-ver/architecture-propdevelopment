Включены только те разделы, которые прямо влияют на приоритетные риски. Исключены второстепенные вопросы (например, физическая безопасность ЦОД), так как они менее значимы для цифровых сервисов PropDevelopment.

**I. Управление доступом**

*Почему важен?*

- Утечки данных чаще всего происходят из-за слабого контроля доступа (например, уволенный сотрудник сохранил доступ к CRM).
- Онлайн-сделки требуют строгой аутентификации.

*Ключевые проверки:*

- MFA для CRM и финансовых систем.
- Аудит привилегированных учётных записей (например, доступ к client-mart-db).
- Блокировка экс-сотрудников в Active Directory.

**II. Безопасность данных**

*Почему важен?*

- Штрафы за нарушения GDPR/ФЗ-152 могут достигать 4% от оборота компании.
- Резервные копии должны быть защищены от ransomware-атак.

*Ключевые проверки:*

- Шифрование БД с персональными данными (crm-db, tenant-core-db).
- Тестирование восстановления из бэкапов.
- Контроль целостности данных в DWH.

**III. Защита инфраструктуры**

*Почему важен?*

- Гибридная инфраструктура усложняет контроль: облачные сервисы и ЦОД требуют разных политик.
- Открытые порты в тестовых средах — точка входа для хакеров.

*Ключевые проверки:*

- Сегментация сети (отдельные VLAN для продаж, ЖКУ, финансов).
- Сканирование уязвимостей в облачных ресурсах.
- Запрет нешифрованного трафика между микросервисами.

**IV. Управление инцидентами**

*Почему важен?*

- Быстрое обнаружение атак на онлайн-сделки минимизирует финансовые потери.

*Ключевые проверки:*

- Наличие SIEM для мониторинга подозрительных действий (например, массовый экспорт данных из CRM).
- План реагирования на утечки персональных данных.

**V. Специфические аспекты**

*Почему важен?*

- Интеграция с внешними системами (СМЭВ, платёжные провайдеры) требует особого контроля.

*Ключевые проверки:*

- Шифрование данных при передаче в госорганы.
- Ограничение доступа к API (например, client-mart-app).
